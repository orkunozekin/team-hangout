# Quarantined attachments

P2.19 keeps the P2.18 upload grant and adds a production content scanner, metadata stripping, streamed downloads, 24-hour quarantine cleanup, and message linking. `features.attachments` stays off for every organization created by `createOrganization`, which still sets only `features.organizationV2`. Both `features.conversations` and `features.attachments` must be true before a file can be reserved, uploaded, finalized, downloaded, or linked. The native picker and the admin file input stay hidden unless the channel page reports attachments enabled and the caller can post.

## Limits

JPEG, PNG, and PDF only. Each file is at most 10 MiB (`ATTACHMENT_MAX_BYTES`) and at least 1 byte. A caller can hold at most 3 active files (`pending`, `uploading`, `quarantined`, or `ready`) per conversation. The count lives on `organizations/{orgId}/attachmentSlots/{fingerprint}` so the check reads one slot and at most 3 attachment documents. Rejected rows drop out of the slot. Expired `pending` and `uploading` rows are marked rejected on the next reservation for that caller. Linking a ready file removes it from the slot. An unlinked ready file keeps the slot.

Client MIME and the PUT `Content-Type` are ignored. The server accepts a file name ending in `jpg`, `jpeg`, `png`, or `pdf` and checks the bytes: JPEG starts with `FF D8 FF`, PNG starts with the 8-byte PNG signature, and PDF starts with `%PDF-`. HTML, SVG, XML, script, MZ, ELF, and a shebang are rejected as `UNSAFE_CONTENT` even when the name looks like a photo. A JPEG named as a PDF, or the reverse, is `SIGNATURE_MISMATCH`. A declared size above 10 MiB is `OVERSIZED` and creates no document. A body whose length differs from the reserved size is `SIZE_MISMATCH`, the reservation is rejected, and nothing is stored.

A message links at most 3 ready attachment ids owned by the author in that conversation. Linking clears those ids from the reservation slot, so the cap applies to files that are not yet on a message. An unlinked ready file still holds its slot. A fourth id, a duplicate, another person's file, a file that is not ready, or a file already linked returns `ATTACHMENT_LIMIT` or `ATTACHMENT_UNAVAILABLE`. Staff notes reject `attachmentIds`. Search tokens come from the message text, not the file name.

## Upload grant

`createAttachmentUpload` returns a 5-minute HMAC grant (`ATTACHMENT_EXPIRY_SECONDS` is 300). The token binds version, expiry, attachment id, owner, organization, reserved size, and object path. Replaying the same request id returns the original token and does not extend the expiry. The same request id with a different payload returns `REQUEST_ID_REUSED`.

The storage emulator cannot mint a GCS signed URL. The development substitute is the HTTP function `attachmentTransport`. In the emulator its URL is `http://127.0.0.1:5001/demo-team-hangout/us-central1/attachmentTransport`. Production uses `https://us-central1-${project}.cloudfunctions.net/attachmentTransport`. A PUT sends `Authorization: Attachment <token>`. The function writes `quarantine/{orgId}/{attachmentId}/1` in the Admin SDK default bucket from `FIREBASE_CONFIG.storageBucket`. Production is `team-hangout-ddf27.firebasestorage.app` and staging is `team-hangout-staging.firebasestorage.app`. The demo emulator configures `demo-team-hangout.appspot.com`. A missing bucket name fails closed. The code does not append `.appspot.com` to the project id. Storage rules deny every client read and write, including the public emulator media URL.

The grant is a bearer capability until it expires, and the PUT also rechecks that the owner can still post. If membership is gone before the bytes are accepted, the object is deleted and the row is `ACCESS_REVOKED`. An expired grant is `EXPIRED` and is not stored. CORS echoes an approved admin origin: the staging and production Hosting origins on `web.app` and `firebaseapp.com`. The emulator also allows `http://127.0.0.1` or `http://localhost` with a port. Other origins, including a wildcard, receive no CORS headers. Auth stays in the Authorization header, so the response does not send `Access-Control-Allow-Credentials`.

The demo emulator signs with the public value `demo-attachment-upload-key-v1-do-not-use-live` when `FUNCTIONS_EMULATOR` is `true` and `GCLOUD_PROJECT` is `demo-team-hangout`. Any other project requires Secret Manager `ATTACHMENT_UPLOAD_KEY` of at least 32 characters. A missing or short secret fails closed. Create that secret before deploying these functions.

## Scanner

The deployed finalizer uses `selectAttachmentScanner`. The mode comes from `platformConfig/attachmentScanner.mode` when that field is set, otherwise from `ATTACHMENT_SCANNER`, otherwise `content`. Clients cannot read or write `platformConfig`. The external URL comes only from `ATTACHMENT_SCANNER_URL`, never from the document.

`content` is the production default. It needs no new secret. It strips JPEG APPn and COM segments and PNG ancillary chunks other than the color and density chunks required to display the image. PDF metadata values (`Title`, `Author`, `Subject`, `Keywords`, `Creator`, `Producer`, `CreationDate`, `ModDate`) are blanked in place, including hex-decoded names such as `/T#69tle`, so the cross-reference offsets stay valid. Trailing bytes after the image end or `%%EOF` are dropped. A PDF name is decoded before it is checked, so `/J#61vaScript` is `/JavaScript`. An active action (`JavaScript`, `JS`, `Launch`, `OpenAction`, `AA`, `RichMedia`, `EmbeddedFile`, `SubmitForm`, `ImportData`, `GoToR`, `GoToE`, or script, HTML, SVG, or XML) is `ACTIVE_CONTENT`. Flate, ASCII85, and ASCII hex streams are inflated or decoded first, including `/Fl`, `/A85`, `/AHx`, and hex-encoded filter names, and the decoded objects are checked again up to four levels. A stream that claims one of those filters but cannot be decoded is `MALFORMED`. `Crypt`, `LZWDecode`, `RunLengthDecode`, and any other non-image filter is `ACTIVE_CONTENT` because its objects cannot be inspected. JPEG, JPX, CCITT, and JBIG2 image streams stay opaque. Cleartext metadata inside a compressed stream is not rewritten. A malformed image is `MALFORMED`. Stripping is idempotent. The stored hash and download are the stripped bytes, not the uploaded bytes.

`unavailable`, an unknown mode, `external` without an `https` URL, or an external scanner that is slow, redirects, returns a non-2xx response, or returns an unclean verdict fails closed as `SCAN_FAILED` or a sanitized rejection code. An external code of `INTEGRITY`, `ACCESS_REVOKED`, `SIGNATURE_MISMATCH`, `EXPIRED`, `OVERSIZED`, `SIZE_MISMATCH`, or `UNSAFE_CONTENT` is stored as `SCAN_REJECTED`. The file is rejected and its object is deleted. There is no production mode that marks every file clean. `developmentScanner` remains in the pure tests and records `scanner: "fake"`. Pre-scan failures and `INTEGRITY` / `ACCESS_REVOKED` record `scanner: "transport"`.

An operator can later set the platform document mode to `external` and provision `ATTACHMENT_SCANNER_URL`. The content scanner still runs first, and the external service receives only the stripped bytes. A missing service never marks a file ready.

## Quarantine, linking, and download

The object is `quarantined` after the PUT. It is not downloadable. `finalizeAttachment` reads the bytes and accepts the upload hash or, after a crash during canonicalization, the stored `canonicalSha256` and its length. Any other hash is `INTEGRITY` and does not call the scanner. When stripping changes the bytes, the row becomes `canonicalizing` before the stripped bytes are written to `quarantine/{orgId}/{attachmentId}/2`. The original upload grant can still name object `/1`, and a PUT while `canonicalizing` is rejected, but it cannot overwrite `/2`. The ready row points at `/2`. A retry uses the canonical length, not the original upload length. That retry still finalizes a matching canonical object after the five-minute grant expires. An expired grant with no matching canonical object is `EXPIRED`. A rejected file deletes the object and leaves the slot. If that delete fails, finalize returns unavailable and the same request id retries the delete before returning the stored receipt.

`postConversationMessage` may include `attachmentIds`. The same transaction creates the message, sets each row's `messageId`, and removes those ids from the author's slot. Replay returns the stored receipt and does not link again. The channel page returns `attachments: [{ id, fileName, detectedType, byteLength }]` for ready rows whose `messageId` is that message. A tombstone hides the attachments.

`GET attachmentTransport` requires `Authorization: Bearer <Firebase ID token>` plus `X-Org-Id`, `X-Scope-Type`, `X-Scope-Id`, and `X-Attachment-Id`. Every download rechecks the live conversation read. A linked file also requires the message to exist, to not be tombstoned, and to list that attachment id. An unlinked ready file remains downloadable by a conversation reader. There is no saved download URL. The handler checks object metadata, reads the object once, and returns those exact bytes only when their hash and length match the ready record. A mismatch or storage miss returns 404 before a body. The response `Content-Type` is the detected type, with `Content-Length`, `Cache-Control: private, no-store`, and `X-Content-Type-Options: nosniff`. A guardian can download a staff file while youth posting is closed, because download uses read access. Direct messages are rejected with `YOUTH_POLICY`.

`purgeAttachmentQuarantine` runs every 60 minutes. It deletes `pending`, `uploading`, `quarantined`, `canonicalizing`, and `rejected` rows whose `createdAt` is at least 24 hours old, drops those ids from the owner slot, and deletes the object. Ready rows stay. Each run lists a bounded page of `quarantine/` and saves `platformConfig/attachmentPurge.objectPageToken`, so a later run continues instead of rereading the same prefix. The listing accepts generations `/1` and `/2`. A quarantine object is deleted only when its storage clock is at least 24 hours old and it is not the path recorded on a ready row. A ready `/2` stays, and an old `/1` beside it is removed. An unknown clock is kept.

File bytes and base64 stay out of messages, `messageSearch`, staff notes, notifications, and the outbox. The message stores the attachment ids and the page shows the file name, detected type, and stripped length. Account deletion retains a message-linked file under organization retention, replaces `ownerUid` with the non-login `Deleted user` identity, and keeps live conversation authorization on every download. Unlinked and unfinished uploads are deleted with both possible object generations and their slot.

## Clients

Native `ConversationScreen` uses `expo-document-picker` with `copyToCacheDirectory: true`, the SDK 54 `File` size, and `expo/fetch` for the PUT and GET. It shows scanning, rejected, and ready text, and sends up to 3 ready ids with the next message. The dev client must be rebuilt before a device can load those native modules. Admin web uses the same HTTP contract with `fetch`. The picker itself was not opened on iOS or Android. That check is in `docs/phase-2-ui-qa-backlog.md`.

## What P2.20 should watch

The content scanner is the built-in gate. It decodes Flate, ASCII85, and ASCII hex PDF streams before looking for active names, and it rejects filters it cannot inspect. It is not a separate malware appliance, and it does not rewrite metadata that lives only inside a compressed stream. A separate malware service is optional and fail-closed. Production still needs `ATTACHMENT_UPLOAD_KEY` of at least 32 characters. Account deletion audit fields contain counts and timestamps only. Storage deletion happens before the Firestore checkpoint for an unlinked upload, so retrying is safe after a crash. A crash after the original storage write and before the quarantine transaction can still leave an object until account deletion or the 24-hour orphan purge. That purge covers both `/1` and `/2` and resumes from `platformConfig/attachmentPurge.objectPageToken`. A matching canonical object can still be finalized after the upload grant expires. The roster import bucket still falls back to `<project>.appspot.com`. `features.attachments` stays off until an operator enables it per organization. Finalize and download each hold up to 10 MiB in a 512 MiB function. The pilot drills and the staging index check are in `docs/phase-2-pilot-runbook.md`.
