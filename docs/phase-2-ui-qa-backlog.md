Living list of flows that still need a real iOS simulator or Android device. This Linux cloud VM has no Mac, no iOS simulator, and no Android emulator. Update this file in the PR for each Phase 2 step.

## P2.18 Attachment transport spike

- **PR:** [#42](https://github.com/orkunozekin/team-hangout/pull/42) on `codex/p2-18-attachment-transport`.
- **Screen / flow:** Admin web workspace at `/organizations/{orgId}/conversations` shows Development attachment only when the server enables attachments and the caller can post. The control accepts a JPEG, PNG, or PDF, uploads it, and shows a ready line after the download matches. Native `ConversationScreen` shows Choose a JPEG, PNG, or PDF under the same conditions and uses the document picker, the SDK 54 File API, and `expo/fetch`.
- **Reproduce:** Rebuild the dev client so `expo-file-system` and `expo-document-picker` are in the binary. Use project `demo-team-hangout`. Create or reuse an organization with `features.conversations` and `features.attachments` both true, and approve `policies.youthChannels` when the signed-in person is a guardian. Open the team channel. On iOS and on Android, pick a real JPEG and a real PDF. Then pick a file larger than 10 MB. Separately, reserve an upload and wait past the 5-minute grant before sending the bytes.
- **Expected:** The JPEG and the PDF each show a ready line with the detected type and the byte length. The oversized file is rejected before the upload. The expired grant is rejected and cannot be downloaded. The household channel and staff notes do not contain the file bytes. An organization with attachments left off does not show the picker. A guardian can read a staff file while youth posting is closed and cannot reserve one until the policy is approved.
- **Unverified platforms:** iOS and Android. This Linux VM cannot open the native document picker or transfer a file through the device File API. The admin page was used to prove the same HTTP contract with a tiny JPEG whose download matched.
- **Verified here:** Node 22.23.3. Functions build, native `yarn typecheck`, native Jest 270/270 with coverage thresholds met, pure scan tests 3/3, attachment emulator tests 5/5, conversation, search, and rules emulator tests, and Playwright Chromium 56/56. One inspected 1440px desktop screenshot shows the ready JPEG line, an empty household channel, and empty staff notes. SHA-256 `586c8c25df2eb1fe5ae9ff2d863fe5e5b2afaf71a376668b78071b624d3a44fe`. Native picker, device JPEG and PDF transfer, oversized rejection, and expired-grant rejection were not run on a device.
- **Risks:** The web capture is a staff session on an organization that explicitly enabled `features.attachments`. It does not prove the native picker, a real camera photo, or a multi-megabyte PDF on a device. The fake scanner marks every well-formed file clean. Ready files are not linked to messages. Account deletion does not anonymize attachment owners.

## P2.17 Corrections, reactions and searchable history

- **PR:** [#41](https://github.com/orkunozekin/team-hangout/pull/41) on `codex/p2-17-corrections-reactions-search`
- **Screen / flow:** Admin web workspace at `/organizations/{orgId}/conversations`, plus native `ConversationScreen`. Staff can edit their own announcement, remove another message, add a reaction, and search the household channel. The native screen has the same search field, edit action, reaction buttons, and edited or removed message text.
- **Reproduce:** Use the demo project `demo-team-hangout` and the admin emulator build. Organization `browser-conversations` has `features.conversations` and no youth policy. Sign in as `browser-conversations-owner@example.test` / `SyntheticPassword123!`. Open `/organizations/browser-conversations/conversations`, choose Team channel, enter scope id `browser-search-team`, and open the channel. Post `Practice is at the north field`, edit it to `Practice moved to the south field`, post `Bring orange slices`, remove that message with reason `Duplicate`, react with the thumbs-up, save the staff note `Guardian phone is private`, and search `south`. On a device, open the same team channel as a guardian after youth posting is approved.
- **Expected:** The channel shows the edited south-field text, an Edited marker, and Message removed by a moderator. Search results show the south-field text and omit the removed text and the staff note. A later search for `orange` says No matching messages. On a device, the guardian can search, edit their own message, and toggle a reaction. A revoked guardian sees the unavailable conversation and gets no search results. While youth posting is closed, the guardian can read but cannot post or react.
- **Unverified platforms:** iOS and Android. No simulator or device was available. A later device pass should open `ConversationScreen` from the household calendar, edit a guardian's own message, toggle a reaction before and after the youth policy is approved, continue a search that reports more matches, and confirm a revoked guardian sees no results.
- **Verified here:** Node 22.23.3. Functions build, native `yarn typecheck`, native Jest 262/262 with coverage thresholds met, conversation emulator tests 11/11, token tests, rules denies for reactions, edit audits, and the search index, staging endpoint counts, and Playwright Chromium 54/54. One inspected 1440px desktop screenshot shows the edited south-field message, the Edited marker, the removed message, a thumbs-up count of 1, the search hit, and the staff note only under Staff notes. SHA-256 `369dfdadd388658b5b1a00dbe6d6288556cd6001667c09badb806993c680fce7`. Native search, edit, and reactions were exercised by rendered tests, not on a device. Review fixes for stale search results, historical index backfill, exact-page continuation, and the cursor key were rechecked with conversation emulator tests 13/13, the screen test, and the conversations Playwright spec 4/4. The second review's native in-flight search guard, restart cursor, and transactional index re-read were rechecked with the conversation emulator suite and the screen test. The screenshot was not recaptured.
- **Risks:** The web capture is a staff session. It does not prove the native composer, reaction row, or search continuation on a device. `features.conversations` stays off until an organization enables it. Staff notes stay out of search. Account deletion does not anonymize message authors. Attachments are not part of this step.

## P2.15 Server RSVP reminders and staff diagnostics

- **PR:** [#39](https://github.com/orkunozekin/team-hangout/pull/39) on `codex/p2-15-rsvp-reminders`
- **Screen / flow:** Admin web workspace, Delivery diagnostics at `/organizations/{orgId}/diagnostics`. Two sections: Delivery failures and Unacknowledged critical updates. No new native screen. The existing inbox should show the title `RSVP reminder` only after a server reminder expands and someone opens that inbox on a device.
- **Reproduce:** Use the demo project `demo-team-hangout` and the admin emulator build. Organization `browser-diagnostics` (Cedar Diagnostics) is schema version 2, status active, with `features.organizationV2` and `features.adminWorkspace`. Sign in as `browser-diagnostics-owner@example.test` / `SyntheticPassword123!`, an active org admin. Seed `organizations/browser-diagnostics/deliveryIssues/bounce` (`channel` email, `status` permanentFailure, `failureCode` EMAIL_BOUNCED, `templateKey` rsvpReminder, `updatedAt` 2026-10-20T15:00:00.000Z) and `deliveryIssues/expired` (`channel` push, `failureCode` DeviceNotRegistered, `updatedAt` 2026-10-20T14:00:00.000Z). Store a recipient email and push token on the bounce row only to prove they stay hidden. Seed `criticalUpdates/closure` with title `Facility closed`, `templateKey` facilityClosure, `sourceRevision` 4, `acknowledgedAt` null, and `createdAt` 2026-10-20T13:00:00.000Z. Open `/organizations/browser-diagnostics/diagnostics`. Then set the member `status` to `revoked` and dispatch a window focus event.
- **Expected:** EMAIL_BOUNCED, DeviceNotRegistered, and Facility closed are visible together. Copy says a transport failure is not an acknowledgement, and the critical card says Not acknowledged. The address, push token, and recipient id are absent. Revocation clears both lists and shows an alert. A 390px-wide browser does not scroll sideways. With the member active again, 26 older failures (`page-0` code `OLDEST_FAILURE`, the rest `PAGE_FAILURE`, `updatedAt` from 2026-10-01) stay off the first page. Show more delivery failures reveals `OLDEST_FAILURE` and still hides the address.
- **Unverified platforms:** iOS and Android. No simulator or device was available. A later device pass should open the existing inbox after an RSVP reminder expands, including denied push permission and a cold start.
- **Verified here:** Node 22.23.3. The first head had Functions build, native `yarn typecheck`, the full backend emulator suite at 253/253, and Playwright Chromium. One inspected 1440px desktop screenshot of the seeded diagnostics page remains that original capture. The same spec checks the 390px width without a second screenshot. Review fixes were rechecked with the reminder plan tests (3/3), `rsvp-reminders.test.mjs` plus `notifications.test.mjs` (32/32), and the diagnostics Playwright spec, including Show more. The screenshot was not recaptured.
- **Risks:** The web capture does not prove native inbox rendering, Expo push, or a physical bounce webhook. Sends stay off until `features.rsvpReminders` and the existing channel flags are enabled. Bulk publication does not write reminder docs inside a publication chunk; the start scan and the deadline scan prepare them.
