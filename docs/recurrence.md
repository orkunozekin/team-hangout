# Recurring practice drafts

P2.04 adds `previewRecurrenceDraft`, `saveRecurrenceDraft` and `getRecurrenceDraft`, plus `/organizations/:orgId/recurrence` in the existing browser workspace. This creates finite staff-only practice drafts, not events. No publication worker, scheduling lease, outbox, family projection or resource reservation is created. Existing event/lifecycle/legacy services are unchanged.

Supply the canonical team ID, title, inclusive local season dates, selected weekdays, local start time, IANA timezone, elapsed duration, explicit excluded dates and optional facility/resource IDs. The initial pilot bounds dates to 2000–2099, at most 112 inclusive calendar days and 64 occurrences before exclusions. Exclusions must be scheduled dates in that range. A season must have explicit dates and the range must fit them. Broader seasons can use separately reviewed finite ranges. The browser defaults to the authorized organization's timezone; it never guesses a missing zone.

The pure generator iterates local calendar dates. UTC midnight is only the representation of a calendar date for iteration; recurrence instants are resolved separately using the selected IANA zone. Spring gaps have no instant and must be corrected or explicitly excluded. Repeated times present actual UTC offsets; the selected offset is stored with the resolved UTC start/end. Half-hour changes and skipped dates are covered. Duration is elapsed minutes, including DST transitions. An offset is per occurrence, never a global silent earlier/later default.

Occurrence identity hashes organization plus series identity, followed by local date and fixed practice slot. It excludes revision, title and UTC time, so local-time edits preserve identity and tenant series IDs cannot collide. Changing/excluding a date changes the current finite set while immutable revision snapshots retain the old set. These identities are reserved for future publication; no event exists yet.

Every read/save/replay checks current account availability, canonical staff scope, program scope, team/hierarchy references and both organizationV2/adminWorkspace flags. Coaches, guardians, platform support and navigation pointers do not grant staff authority. Drafts and revisions remain default-denied in Firestore rules, including to staff clients; callable responses allowlist only draft editor data. Current author/receipt metadata uses the existing account deletion/retention contract; no new user discovery/access collection is added.

Preview reuses the resource validator for current catalog status, sport, effective availability, existing bookings and setup/cleanup buffers, with within-draft overlap diagnostics. It limits query result documents to 1,000 across the preview (one final bounded query may cross that threshold before rejection), and existing reservation queries still fail closed above 500 candidates. Document snapshots are cached only within a transaction attempt. A draft may retain explicitly reviewed resource conflicts; it does not promise availability. Future publication must independently revalidate all constraints and reserve resources under its own fence.

Saving requires the preview hash and explicit review confirmation. A transaction regenerates the finite set and current resource diagnostics/snapshots; changed preview conditions require another review. Series revision and request receipt protect concurrent edits and duplicate execution. Successful receipt replay returns the original result only after live authority checks, without adding revisions. Each save atomically writes the current series, immutable revision snapshot and audit. No catalog/resource history is modified.

The editor clears preview/review confirmation on edits, retains exact payload/request ID on uncertain saves and disables input until retry resolves. Auth/navigation unmounts tenant state; focus rechecks current workspace scope. Revocation clears editor data and fences pending responses. Existing drafts are loaded by their ID and re-previewed before revision. The bounded initial editor uses canonical IDs as the existing resource-assignment screen does; richer draft administration belongs to P2.06.

Validation is emulator/pure/browser evidence only. Deploy the three callables before exposing this route in a live workspace; no deployment, rollout flag, migration or production write is part of this change. Rollback removes the route/writers while retaining private series revisions and receipts. P2.05 scheduler feasibility and P2.07 bulk publication remain separate steps.
