# Private league schedule drafts

P2.06 adds `/organizations/:orgId/drafts` to the existing web administration app. Staff enter explicit UTC slots, game duration, minimum team rest, repetitions and seed. Repeatable controls add team blackouts and preferred slots. UTC input makes DST offsets explicit; the season timezone, falling back to the organization timezone, defines the season calendar bounds. No local timezone or duration is guessed.

`generateScheduleDraft` persists the bounded pure scheduler's result, including complete, impossible partial, and budget-exhausted partial schedules. `saveScheduleDraft` accepts manual assignments and changed constraints at the expected revision and clears validation, validation revision, input hash and generation diagnostics. `validateScheduleDraft` independently checks saved assignments against a new authoritative snapshot and creates a new revision. `getScheduleDraft` reloads a private record; the editor requires revalidation after reload or focus. Every mutation has an exact idempotency request ID and immutable revision/audit history. Changed payload reuse and stale concurrent writes fail. Successful receipt replay rechecks current access and never overwrites later state.

Every read, mutation and replay requires current organization staff, the division's program grant, canonical hierarchy/team ownership and active hierarchy, plus `organizationV2`, `adminWorkspace` and `scheduler` server flags. Platform support, coach, guardian, self-player and navigation pointers grant no staff authority. Client-supplied actor IDs, grants, busy snapshots or resource availability are rejected. All active division teams are discovered rather than silently accepting a subset. The server reads current coach assignments across the same organization so shared coaching with another program's games can block assignments, but returns only conflict categories and the authorized division's team labels. It never queries another organization or returns coach identities, other-division team names, event details or roster records. Cross-organization coach conflicts are explicitly not checked.

The server reads current resource/facility status, sports, buffers and immutable effective availability. Buffered occupancy must fit one effective revision, including exact boundary behavior. Gameplay stays inside the selected range and canonical season dates; setup/cleanup may extend outside the draft range when authoritative availability covers them. Existing published scheduled/completed reservations and current team/coach occupancy are independently checked. Private drafts never reserve a resource, so validation is a point-in-time observation. Any future publication must re-read current inputs and implement P2.07's separate safety protocol.

## Bounds and honest limitations

The pure bounds remain 32 teams, 16 elapsed weeks, 1,000 slots, 32 resources, 1,000 busy intervals, 128 intervals per entity and two round-robin cycles. Search stops at 100,000 nodes or 10 seconds, including preparation; independent validation runs separately. A known feasible 32-team example retains 446 of 496 games at the node budget. No reliable maximum-size completion, global optimality or production capacity is claimed. Odd byes describe pairing rounds, not calendar weeks. A hard-valid partial is still incomplete, and exhausted search is never relabeled impossible.

The adapter deliberately uses conservative tenant-wide bounds: at most 1,000 current organization assignment documents and 1,000 organization event documents, with one sentinel beyond each bound. Event history, staged/deleted rows and unrelated programs can cause the conservative event bound to reject a request before filtering. It reads each resource's availability history once, at most 128 revisions, and accepts at most 5,000 snapshot query documents, plus bounded canonical document reads for up to 32 teams/resources. Oversized input fails with guidance rather than truncating constraints or occupancy. Normal four-team/single-resource generation needs one team query, one staff-assignment query, one event query and one availability query, with request-local document reuse. Real index readiness, latency and larger-tenant capacity remain staging/pilot gates.

Draft records have an 800 KB serialized budget, leaving space below Firestore's record limit. Conflict details retain at most 1,000 entries with the full count and explicit truncation indicator. The editor pages fixtures in groups of 20, slot editors in groups of 10, blackout intervals in groups of five per team constraint, and preference/assignment slot choices in groups of 20. Page controls can jump directly to a numbered page; selections persist across pages and the current assignment stays visible even when its slot is on another page. Removing a slot unassigns affected fixtures and invalidates validation. Fairness metrics remain separate from hard validity. Original generation status remains labeled as generation history after current revalidation; edits clear it.

## Privacy, rollout and rollback

`organizations/{orgId}/scheduleDrafts/{draftId}` and its immutable `revisions` are server-only private organization operational records. Direct client reads and writes are denied, including for staff. The persisted payload contains constraints, authorized division team labels/fixture references, assignments and safe diagnostics, never transient coach identities or raw occupancy snapshots. Canonical team IDs of up to 128 characters map to bounded internal scheduler IDs; fixture handles stay opaque and staff results retain the full canonical team IDs. Standard schema/revision/server timestamp/actor metadata and private audit apply. These are organization-owned operational history under `docs/account-deletion.md`; deleting an account removes its command receipts and grants, preserves operational/audit history, and the account tombstone denies all draft callables immediately. No new account-owned collection or token is added.

P2.06 originally left `publishScheduleDraft` disabled after live authorization. P2.07 now implements the separate [resumable publication protocol](schedule-publication.md). P2.06 itself created no events, reservations, outbox intents, scheduling fences or publication operations. Existing unrelated single-event and CSV import APIs are unchanged; they cannot adopt a schedule draft or bypass this disabled endpoint. P2.07 owns any later schedule-draft publication.

No flag is enabled and no deployment, production read/write or migration is performed. New indexes declare active division-team and organization assignment query shapes; deploy and verify them in staging before any rollout. Rollback disables `scheduler` and retains private draft/history records. Do not delete them or bypass branch protections.

## Validation

Use Node 22. Run a separately successful `yarn --cwd functions build` before backend tests, `yarn test:backend`, `yarn test:scheduling`, the seeded benchmark, native typecheck/unit tests and `yarn test:admin`. The focused operations gate includes draft and deletion tests. Regression coverage includes nonempty generated fixture edits (fixture IDs contain colons), dirty validation, concurrency/replay, finite impossible and known-feasible exhausted search, buffer/range and immutable availability boundaries, live grants/flags/hierarchy, private direct access, coach conflict privacy and explicit overflow. Browser tests exercise real generation/edit/save/revalidation, partial results, exact uncertain retry, stale revisions and focus revocation with a held response. A real accepted 1,000-slot/32-team generated draft is loaded through the callable, checks bounded editor/option counts, jumps to the final pages and saves without losing off-page preferences or assignments. A separate accepted 32-team draft contains all 128 blackouts per team and verifies bounded interval inputs and hidden interval preservation after editing the final page. UI evidence uses two original inspected screenshots for complete and partial schedules, with provenance in the PR and handoff. Review fixes retain those images unchanged.
